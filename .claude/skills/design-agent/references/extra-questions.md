# 조건 축에 없는 질문

`recommend.mjs` 점수는 다섯 조건(플랫폼·쓰는 빈도·기기·콘텐츠·작업의 무게)만 본다. 아래 패턴은 축에 없는 사실 하나로 답이 크게 바뀌니, 그 패턴을 물을 때 같이 묻고 점수 추천을 고친다. 고쳤으면 「점수는 X였지만 선택지가 3개뿐이라 Y로 바꿨다」처럼 이유를 말한다.

## 불러오는 동안 (loading) — 「보통 얼마나 기다리나요?」
- 이 패턴은 상황이 넷이다(`recommend.mjs` 결과의 「상황」 줄). 1초 안에 끝날 때(표시 안 함), 화면을 처음 열 때(스켈레톤·스피너), 내가 바꾼 것이 저장되는 동안(바로 반영), 결과를 만드는 동안(진행 바·그림과 진행 문구). 서비스에 있는 상황마다 하나씩 고른다. 입력하면 바로 다시 계산되는 계산기처럼 기다릴 것이 없으면 「표시 안 함」 하나로 끝난다
- 화면을 여는 로딩·목록 불러오기는 사용자 동작이 아니다. `--action none`으로 따로 계산한다. 그러지 않으면 「가벼운 작업」 때문에 「바로 반영」이 추천된다(바로 반영은 좋아요·저장처럼 사용자가 바꾼 것을 먼저 보여 줄 때만 맞다)
- 1초 미만: 로딩 표시를 하지 않는다
- 1~4초: 틀이 정해진 목록·카드면 스켈레톤, 작은 영역이나 버튼이면 스피너
- 4~10초 이상: 진행 바와 지금 하는 일 문구
- 1분 이상: 뒤에서 처리하고 끝나면 알린다, 취소를 준다
- (디자인 시스템 여러 곳의 공통 기준. `/systems/` 참고)

## 하나 고르기 (single) — 「선택지가 몇 개고, 얼마나 긴가요?」
- 2~4개이고 짧다: 세그먼트(다 펼쳐 한 줄로). 점수가 라디오·드롭다운을 줘도 바꾼다
- 5개 이상이거나 설명이 길다: 라디오 목록(데스크톱·글 중심), 아주 많으면 드롭다운
- 처음·한 번만 쓰는 사람, 여럿이 쓰는 기기: 큰 버튼(타일)

## 카테고리 이동 (category) — 「분류가 몇 개인가요?」
- 5개 이하: 상단 탭
- 6개 이상이고 모바일: 가로로 밀리는 칩
- 6개 이상이고 데스크톱: 왼쪽에 세로로 펼친 목록(레일)
- 분류 안에 또 분류가 있으면: 왼쪽 목록에 묶음 제목

## 목록이 길 때 (more) — 「한 번에 몇 개쯤 보이나요? 끝까지 보나요?」
- 한 화면 분량이면 나누지 않는다
- 검색 결과·게시판처럼 위치를 기억해야 하면 페이지 번호
- 둘러보는 피드면 모바일은 더보기 버튼이나 무한 스크롤(바닥글·합계가 있으면 무한 스크롤 피함)

## 켜고 끄기 (toggle) — 「바로 적용되나요, 저장해야 적용되나요?」
- 바로 적용: 토글 스위치
- 저장 버튼을 눌러야 적용: 체크박스

## 입력 확인 시점 (validate) — 「칸이 몇 개인가요?」
- 두세 칸뿐인 짧은 폼: 제출할 때 모아서 확인해도 된다
- 칸이 많은 폼: 칸을 벗어날 때 확인한다(덜 친 칸에 오류부터 띄우지 않는다)
- 계좌번호·아이디 중복처럼 바로 확인할 수 있는 칸: 입력하는 동안
- 플랫폼은 기준이 아니다. 모바일 폼도 같다 (2026-10-30 점검)

## 실패했을 때 (error) — 「무엇이 실패하나요? 칸 하나인가요, 화면 전체인가요?」
- 입력 칸 하나: 그 자리에 문구
- 화면을 아예 못 불러옴: 전체 화면 + 다시 시도
- 결제·인증처럼 다음에 할 일을 골라야 함: 대화상자
- 토스트로 오류를 알리면 금방 사라져 놓친다. 가벼운 일에만

## 확인 단계 모양 (confirmForm) — 「확인 전에 다시 볼 내용이 몇 줄인가요?」
- 두세 줄(삭제 확인 등): 대화상자(모바일은 아래 시트도 된다). 되돌릴 수 없는 삭제도 대화상자가 표준이다
- 주문 내역·금액처럼 줄이 많으면: 확인 화면

## 비어 있을 때 (empty) — 「왜 비어 있나요?」
- 상황이 셋이다. 처음이라 아직 없을 때(다음 행동 버튼·그림 + 문구), 찾기·거르기 결과가 없을 때(조건 보여 주고 풀기), 표·목록 안 한 칸이 빌 때(문구 한 줄). 점수만 보면 셋이 섞이니 상황부터 정한다
- 거르기 조건이 하나도 안 걸렸는데 0개면, 그건 「처음이라 없음」이다(아직 올라온 것이 없다). 「0 results」만 두지 말고 언제 생기는지, 무엇을 할 수 있는지 적는다(2026-11-02 실제 서비스 시험)

## 화면 사이 이동 (nav) — 「큰 메뉴가 몇 개인가요?」
- 휴대폰 하단 탭바는 3~5개(Material·Apple·토스). 6개 이상이면 점수가 하단 탭바를 줘도 바꾼다: 자주 쓰는 4개 + 「더보기」, 또는 위쪽 메뉴
- 데스크톱에서 5개 안팎이면 위쪽 메뉴, 많거나 매일 쓰는 업무 도구면 왼쪽 사이드바

## 끝났다고 알릴 때 (done) — 「결과를 들고 가야 하나요?」
- 복사·저장처럼 누른 자리에서 끝나는 일: 그 자리 결과 문구(버튼 글자를 잠깐 바꾼다). 토스트는 화면 구석이라 놓치고, 스크린리더가 못 읽는 경우가 있다(Primer)
- 주문 번호·이체 결과처럼 들고 갈 것이 있으면: 완료 화면
- 실패했는데 성공 문구를 띄우지 않는다(복사 실패에도 「Copied」가 뜨던 실제 서비스가 있었다)

## 올리기 (upload) — 「어떤 파일을, 몇 번 올리나요?」
- 받을 때: 컴퓨터 폴더에서 올리면 끌어 놓기 칸, 휴대폰이면 파일 고르기 버튼. 둘 다면 칸 안에 버튼을 같이 둔다
- 올린 뒤: 몇 개·몇 줄을 받았는지, 무엇이 안 됐는지를 칸 자리에 남긴다. 같은 파일을 두 번 올리면 데이터가 두 배로 쌓이지 않게 알린다(2026-11-02 실제 서비스 시험)

## 동의 받기 (consent) — 「동의 항목이 몇 개고, 선택 항목이 있나요? 나중에 물을 순간이 오나요?」
- 다섯 개가 넘으면 모두 동의 + 항목 펼치기, 두세 개면 필수·선택 나눠 받기. 점수는 항목 수를 모른다
- 마케팅 알림·위치 정보처럼 처음엔 없어도 되는 동의는, 다시 쓰는 서비스면 그 기능을 켤 때 묻는다(쓰는 순간에 묻기)
- 어느 방식이든 미리 체크하지 않고, [필수]·[선택]을 글로 쓰고, 「동의 안 함」을 둔다(UX 기준 속임-1·입력-5, KRDS 동의)

## 권한 요청 (permission) — 「누른 버튼만 보고 왜 필요한지 뻔한가요?」
- 카메라 버튼을 눌러 카메라를 묻는 것처럼 뻔하면 바로 시스템 창. 알림·위치처럼 이유가 안 보이면 이유를 먼저 말한다. 쓰는 빈도보다 이것이 먼저다
- 거절한 뒤에는 창을 다시 띄워 조르지 않는다. 그 기능을 다시 누를 때만 왜 안 되는지와 「설정에서 켜기」, 대신 쓸 길을 보인다(Android 권한 문서)
- 앱을 열자마자 묻지 않는다(UX 기준 속임-6·방해-1)

## 세션 만료 알림 (session) — 「로그인이 왜, 몇 분 뒤에 끝나나요?」
- 보안 때문에 정한 시간이면 끝나기 전 경고 + 연장(KRDS 로그인은 20초 전 이상, DWP는 2분 전). 아무것도 안 할 때만 끝나면 쓰는 동안 자동 연장
- 어느 쪽이든 끝난 뒤에는 다시 로그인하면 쓰던 화면과 값으로 돌아가게 한다(UX 기준 누구나-8)
- 로그인이 없는 서비스면 묻지 않는다

## 만족도 요청 (survey) — 「앱인가요, 웹인가요? 끝이 분명한 일이 있나요?」
- 스토어에 올린 앱만 스토어 평가 요청을 쓸 수 있다. 앞에 「마음에 드세요?」를 묻지 않고 버튼에 걸지 않는다(Google Play 인앱 리뷰 지침)
- 주문·예약처럼 끝이 분명하면 그 건의 별점, 안내·신청 글이면 끝난 자리에 한 줄
- 매일 쓰는 도구는 묻지 않고 「의견 보내기」 링크만 둔다

## 도움말 방식 (help) — 「무엇을 설명하나요? 칸 하나인가요, 서비스 전체인가요?」
- 형식·글자 수처럼 쓰는 데 꼭 필요한 것은 누구에게나 칸 옆 도움말 글로 늘 보인다
- 일부만 모르는 용어는 펼치는 도움말, 막혔을 때 찾는 것은 도움말 센터, 사람이 답해야 하는 것(환불·사고)은 상담
- 도움말·상담으로 가는 길은 모든 화면 같은 자리에 둔다(WCAG 2.2 3.2.6)

## 신청 뒤 진행 상태 (tracking) — 「단계가 정해져 있나요?」
- 접수 → 검토 → 완료처럼 정해져 있으면 단계 표시, 문의·배송처럼 일이 오가면 시간순 기록. 둘을 같이 써도 된다(위에 단계, 아래에 기록)
- 어느 방식이든 다음에 무엇이 언제 오는지 적는다(KRDS 신청 결과 확인, Baymard 주문 추적). 마친 순간의 화면은 「끝났다고 알릴 때」
