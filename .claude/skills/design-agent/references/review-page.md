# 리뷰 페이지

리뷰를 글로만 주면 무엇이 바뀌는지 안 보이고, 긴 리뷰는 어디부터 읽을지 모른다(2026-11-10 사용자). 리뷰를 다 쓰면 `review.json`으로 적고 페이지 하나로 만들어 연다. 대화에는 「먼저 고칠 셋」 세 줄과 페이지 경로만 답한다.

```
node .claude/skills/design-agent/scripts/review-page.mjs 리뷰폴더/review.json
open 리뷰폴더/review.html
```

- 페이지는 파일 하나다. 사진은 페이지 안에 넣는다(base64). 밖에서 불러오는 것이 없다
- 넓은 화면에서는 고치기 전·후를 나란히, 좁은 화면에서는 「고치기 전 / 고친 뒤」 버튼으로 같은 자리에서 바꿔 본다
- 남의 서비스 화면이 들어가면 이 PC의 파일로만 둔다. 사용자 자신의 서비스이고 사용자가 원할 때만 공유 링크로 올린다(올리기 전에 묻는다)
- 사진 파일을 못 찾으면 그 자리에 「사진 없음」을 두고 끝 코드 2로 끝난다

## 사람 판정

페이지의 항목마다 「지적이 맞나(맞다·틀렸다·모르겠다)」「처방은(그대로·고쳐서·못 쓴다)」와 메모가 있다. 고른 것은 그 브라우저에만 남고, 「판정 내려받기」로 `review-judgments.json` 하나를 받는다. 받은 파일은 리뷰 폴더에 두고, 「틀렸다」「못 쓴다」가 나온 항목을 원인별로 묶어 `visual-basics.md` 규칙과 `test:skill` 시험 사례로 옮긴다. 에이전트끼리 읽혀 보는 것은 거름망이고, 맞는지는 그 일을 하는 사람이 정한다(2026-11-10 사용자)

## review.json

모든 칸은 빠져도 된다. 글에는 `**굵게**`, `` `코드` ``를 쓸 수 있고, 값 끝의 `(잰 것)`·`(계산한 것)`·`(눈으로 본 것)`·`(눌러 본 것)`·`(코드에서 본 것)`·`(내 판단)`은 작은 출처 표시로 바뀐다.

```json
{
  "title": "○○ 디자인 리뷰",
  "url": "https://example.com/",
  "date": "2026-11-10",
  "repo": "omt-web @ 1a2b3c4",
  "context": ["남긴 것: 없다", "조건 짐작: 모바일, 가끔 쓴다, 내 폰, 글 중심", "본 화면: 홈, 설정"],
  "fails": ["읽기·누르기 어려움", "헷갈림"],
  "top": [
    {
      "title": "다크 모드에서 머리 막대 제목이 안 보인다",
      "body": "대비 1.02:1(잰 것). 바탕만 흰색으로 고정돼 있다",
      "shots": { "before": "fix1-before.png", "after": "fix1-after.png" },
      "changes": [
        { "n": 1, "text": "화면 제목: 1.02:1 → 15.6:1(계산한 것)" },
        { "text": "번호 없는 줄: 사진으로 안 보이는 변경(대비 등)" }
      ],
      "css": ".topbar { background: var(--surface); }",
      "where": [
        { "file": "src/styles/app.css", "line": 42, "what": "머리 막대 바탕", "before": ".topbar { background: rgba(255,255,255,.94); }", "after": ".topbar { background: color-mix(in srgb, var(--surface) 94%, transparent); }" },
        { "file": "src/styles/tokens.css", "line": 3, "what": "회색 글 토큰", "before": "--muted: #76767f;", "after": "--muted: #6b6b74;", "uses": "`--muted`를 쓰는 곳 14군데(코드에서 본 것)" }
      ],
      "code": "",
      "note": "밝은 모드에서는 지금과 같다"
    }
  ],
  "fixes": [
    { "level": "꼭", "fail": "읽기·누르기 어려움", "text": "「필수」 배지 3.9:1, 10px(잰 것). #d70027로 4.85:1" },
    { "level": "권장", "fail": "빠진 상태", "text": "뒤로 가기가 사이트를 떠난다", "top": 2 }
  ],
  "good": ["색이 한 가지로 묶여 있다(잰 것)"],
  "patterns": [{ "name": "여러 단계 흐름", "now": "한 화면에 한 질문", "rec": "한 화면에 한 질문", "verdict": "맞다" }],
  "askNote": "정한 거면 그대로 두고, 아니면 괄호 안처럼 고친다",
  "ask": ["이모지 아이콘(흔한 기본값)"],
  "unchecked": ["결과 화면(결정을 누르지 않았다)"]
}
```

- `topWhy`: 먼저 고칠 셋을 고른 기준 한 줄. 빠지면 알린다
- `top`: 먼저 고칠 셋. `shots`는 review.json 기준 경로. 구조를 바꾸는 것(뒤로 가기 등)은 `shots` 없이 `code`만 둔다
- `changes`: 사진의 번호 점선과 같은 번호(`n`). 사진으로 안 보이는 변경은 `n`을 빼면 빈 동그라미로 나온다
- `effort`: 걸리는 시간 어림(「10분」「1시간」「반나절」). 먼저 고칠 셋과 꼭·권장 고칠 곳에 넣는다. 빠지면 「넘기기 전에 볼 것」으로 알린다
- `repo`: 읽은 서비스 저장소 이름과 커밋. 넣으면 머리에 「코드: …」로 나오고, 먼저 고칠 셋과 「꼭」마다 `where`가 없으면 알린다. 저장소를 못 읽었으면 뺀다
- `where`: 코드에서 고칠 곳(2026-11-11). 항목마다 `file`(저장소 기준 경로, 이 PC 경로는 알린다), `line`, `what`(무엇인지), `before`(지금), `after`(고친 뒤, 「복사」는 이것만 복사한다), `uses`(바뀌는 범위), `sure: false`(같은 이름이 여러 곳이라 후보). 토큰(`--이름:`)을 바꾸는데 `uses`가 없으면 알린다. 못 찾았으면 `{ "missing": "무엇으로 찾았는지" }`
- `fixes`: 나머지 고칠 곳. `level`은 꼭·권장·확인, `fail`은 실패 이름(`failures.md`). 먼저 고칠 셋과 같은 것이면 `top`에 그 번호를 넣어 연결한다. `shots`·`changes`·`css`·`code`·`where`를 넣으면 「고친 모습 보기」(`where`만 있으면 「코드에서 고칠 곳 보기」)로 접혀 붙는다
- 글(`body`, `fixes[].text`)에서 `- `로 시작하는 줄은 목록이 된다. 자리마다 다르게 고칠 것(이모지: 고르기 칸은 빼고, 방식 카드는 선 아이콘)은 이렇게 줄을 나눠 쓴다(`visual-basics.md` 「이모지」)
- 시험 리뷰: `scripts/fixtures/review/review.json`(`npm run test:skill`이 페이지를 만들고 우리 검사기로 잰다)
