# 서비스 종류별로 먼저 물을 패턴

서비스 종류를 알면 27개 패턴을 다 묻지 않아도 된다. 아래 묶음에서 앞쪽부터 묻고, 사용자가 더 원하면 나머지를 묻는다. 순서는 「사용자가 가장 먼저 만나고, 잘못 고르면 가장 아픈 것」부터다.

괄호 안 조건은 흔한 출발점일 뿐이다. 사용자가 말한 내용이 먼저다.

## 쇼핑몰·커머스 (모바일 · 가끔 쓴다 · 내 기기 · 사진 중심)
1. nav 화면 사이 이동 · search 찾기 · category 카테고리 이동
2. filter 거르기 · more 목록이 길 때 · noImage 사진이 없을 때
3. cta 주요 버튼 자리 · cartPlace 장바구니·합계 자리 · qty 수량 · single 하나 고르기(옵션)
4. steps 여러 단계 흐름(주문서) · confirmForm 확인 단계 모양 · busy 버튼을 누른 뒤 · done 끝났다고 알릴 때
5. loading · empty(빈 장바구니) · error
- 메모: 검색이 핵심이다. 상품 목록은 이미지로 고르면 그리드, 사양으로 고르면 리스트. 상세는 첫 화면에 총 금액까지(마디아 영상 정리, research/madia-uxui.md)

## 매장 주문·키오스크 (태블릿 · 처음·한 번만 쓴다 · 여럿이 쓰는 기기 · 사진 중심)
1. category 카테고리 이동 · single 하나 고르기(맵기·사이즈) · qty 수량
2. cartPlace 장바구니·합계 자리 · cta 주요 버튼 자리
3. confirmForm 확인 단계 모양 · busy 버튼을 누른 뒤 · done 끝났다고 알릴 때
4. error · loading · empty
- 메모: 여럿이 쓰는 기기는 다음 사람이 이어 쓰니 흔적을 남기지 않는다. 처음 쓰는 사람에게 숨은 제스처는 쓰지 않는다

## 금융·송금 (모바일 · 가끔 쓴다 · 내 기기 · 표·숫자 중심 · 되돌릴 수 없는 작업)
1. validate 입력 확인 시점 · steps 여러 단계 흐름 · confirmForm 확인 단계 모양
2. busy 버튼을 누른 뒤 · done 끝났다고 알릴 때 · error 실패했을 때
3. time 시간 표기 · statusMark 상태 표시 · delete 지울 때
4. nav · loading · empty
- 메모: 금액·받는 사람은 한 화면에 크게 확인시킨다. 「바로 반영」처럼 성공을 먼저 보여 주는 방식은 피한다

## 업무 도구·관리자 대시보드 (데스크톱 · 매일 쓴다 · 내 기기 · 표·숫자 중심)
1. nav 화면 사이 이동 · search 찾기 · filter 거르기
2. more 목록이 길 때 · refresh 새로 고칠 때 · statusMark 상태 표시 · time 시간 표기
3. delete 지울 때 · toggle 켜고 끄기 · popover 가벼운 메뉴 열기 · validate 입력 확인 시점
4. loading · empty · error · done
- 메모: 한 화면 정보량이 중요하다. 표는 가로줄을 줄이고 왼쪽 정렬, 한 단계 작게

## 콘텐츠·미디어·커뮤니티 (모바일 · 매일 쓴다 · 내 기기 · 글 또는 사진 중심)
1. nav · category · more 목록이 길 때 · refresh 새로 고칠 때
2. longText 긴 글 · time 시간 표기 · noImage 사진이 없을 때
3. notify 새 소식 알릴 때 · onboarding 처음 안내 · search
4. delete · loading · empty · error
- 메모: 피드는 「3분 전」 같은 짧은 경과 시간, 게시판·뉴스는 날짜를 그대로 적는 경우가 많다(실제 화면 판정)

## 예약·여행 (모바일 · 가끔 쓴다 · 내 기기 · 사진 중심 · 두 번 되면 안 되는 작업)
1. search 찾기 · filter 거르기 · single 하나 고르기(날짜·인원)
2. steps · confirmForm · cta · busy · done
3. time 시간 표기(기간) · error · loading · empty
- 메모: 사진과 위쪽 예약 영역이 핵심이다

## 회사·서비스 소개 웹사이트(랜딩) (데스크톱 · 처음·한 번만 쓴다 · 내 기기 · 글 중심)
- 패턴보다 섹션 구성이 먼저다. 컴포넌트 사전의 랜딩 섹션(landing-menu: 히어로, 신뢰, 기능, 작동, 전환, 뼈대)으로 순서를 정하고, 그다음 nav · cta · onboarding · longText를 묻는다
- 국내 웹사이트는 헤더에 돋보기 아이콘만 두는 경우가 많고, 메뉴가 많으면 메가 메뉴를 쓴다(실제 화면 판정)

## 참고·문서 사이트 (데스크톱 · 가끔 쓴다 · 내 기기 · 글 중심 · 작업의 무게 없음)
디자인 시스템 문서, 개발 문서, 카탈로그, 사내 위키처럼 찾아 읽고 복사해 가는 사이트
1. nav 화면 사이 이동(큰 메뉴 몇 개 → 위쪽 메뉴) · category 카테고리 이동(문서 목록 → 왼쪽 목록) · search 찾기
2. more 목록이 길 때 · longText 긴 글 · empty 비어 있을 때
3. done 끝났다고 알릴 때(복사됨 같은 확인) · toggle 켜고 끄기 · single 하나 고르기
4. loading(`--action none`) · onboarding
- 메모: 큰 메뉴(위)와 문서 목록(왼쪽)은 다른 패턴이다. 문서가 수십 개면 검색이 꼭 필요하다. 복사 확인은 토스트보다 누른 버튼 글자를 잠깐 바꾸는 쪽이 눈에 잘 들어온다

## 어디에도 안 맞으면
`node scripts/recommend.mjs --list`의 묶음(상태 알리기 / 목록과 이동 / 고르기와 입력 / 동작과 확인 / 표시)을 보여 주고, 만들 화면에 나오는 것을 사용자에게 고르게 한다.
