# 모바일 · 가끔 쓴다 · 내 기기 · 사진 중심

## 화면 구조
- 내비게이션: 하단 탭바
- 확인 단계: 결제 전 확인

## 꼭 지킬 것 — 규격·접근성 기준이 있다
- hover 상태에 기대지 않는다. 터치에는 hover가 없다
- 노치·홈 인디케이터 영역(safe area)에 버튼을 두지 않는다
- 사진 위 글자는 대비 4.5:1 이상. 어두운 깔개나 단색 띠를 깐다 (WCAG 2.2 · 1.4.3)

## 보통 이렇게 — 흔히 이렇게 한다. 이유가 있으면 바꿔도 된다
- 주요 버튼은 엄지가 닿는 화면 아래쪽에
- 아이콘에는 글자 라벨을 함께 붙인다
- 플랫폼 기본 패턴을 그대로 쓴다. 새 제스처를 만들지 않는다
- 사진 비율은 하나로 고정한다
- 사진이 없을 때의 화면을 따로 디자인한다
- 사진 둘레에 그림자·테두리를 더하지 않는다

## 참고
- 하단 탭은 3~5개
- 하다 만 작업을 다음에 이어서 할 수 있게

## 시스템에 맡긴 것 — 여기 다시 적지 않는다
- 컴포넌트 모양과 상태, 색·글자·모서리·그림자 값은 시스템(당근 SEED Design) 것을 쓴다. 이 파일에 값을 옮겨 적지 않는다. 두 곳에 적으면 한쪽만 낡는다
- 시스템에 있는 컴포넌트를 새로 그리지 않는다. 없는 것만 시스템 토큰으로 만들고, 새로 만들었다고 알린다

## 패턴별 방식
- 불러오는 동안 (두 번 되면 안 되는 작업 기준): 스켈레톤 — 사진 중심: 사진·카드 자리를 미리 잡아 화면이 튀지 않는다
- 버튼을 누른 뒤 (두 번 되면 안 되는 작업 기준): 문구를 바꾸고 잠근다 — 두 번 되면 안 되는 작업: 두 번 눌러 두 번 가는 것을 막는다
- 비어 있을 때: 다음 행동 버튼 — 
- 실패했을 때 (두 번 되면 안 되는 작업 기준): 알림 대화상자 — 두 번 되면 안 되는 작업: 결제·인증 실패처럼 다음에 할 일을 골라야 할 때 (Lazyweb 실제 앱 화면 4건(copilot, donotpay 등))
- 끝났다고 알릴 때 (두 번 되면 안 되는 작업 기준): 완료 화면 — 두 번 되면 안 되는 작업: 주문 번호·결제 내역처럼 들고 갈 결과를 크게
- 새 소식 알릴 때: 숫자 배지 — 조건과 직접 걸리는 근거 없음, 가장 흔한 방식
- 처음 안내: 가리키는 말풍선 — 가끔 쓴다: 바뀐 것 하나만 알릴 때
- 목록이 길 때: 무한 스크롤 — 모바일 / 사진 중심: 사진을 계속 넘겨 보는 피드
- 새로 고칠 때: 당겨서 새로고침 — 모바일
- 카테고리 이동: 가로 칩 — 모바일: 좁은 폭에서 한 줄로 많이
- 거르기: 칩 필터 — 모바일 / 가끔 쓴다: 자주 쓰는 조건만 바로 누른다
- 화면 사이 이동: 하단 탭바 — 모바일: 엄지가 닿는 곳에서 바로 옮긴다 / 가끔 쓴다: 앱마다 같은 자리라 낯설지 않다
- 찾기: 돋보기 아이콘 — 모바일: 좁은 머리에 자리를 아낀다
- 가벼운 메뉴 열기: 아래 시트 — 모바일: 엄지가 닿는 아래에서 고른다
- 하나 고르기: 라디오 목록 — 조건과 직접 걸리는 근거 없음, 가장 흔한 방식
- 수량: − + 버튼 — 조건과 직접 걸리는 근거 없음, 가장 흔한 방식
- 켜고 끄기: 토글 스위치 — 가끔 쓴다
- 입력 확인 시점 (두 번 되면 안 되는 작업 기준): 칸을 벗어날 때 — 가끔 쓴다: 입력 중에 재촉하지 않는다
- 올리기 (두 번 되면 안 되는 작업 기준): 파일 고르기 버튼 — 모바일: 휴대폰은 사진첩·파일 앱에서 고른다
- 지울 때 (두 번 되면 안 되는 작업 기준): 밀어서 지우기 — 모바일: 목록 정리가 잦은 앱 / 내 기기: 내 목록을 내가 정리할 때
- 확인 단계 모양 (두 번 되면 안 되는 작업 기준): 아래 시트 — 모바일: 버튼이 엄지 닿는 곳에 온다 / 두 번 되면 안 되는 작업: 결제 전 요약을 엄지 닿는 곳에
- 주요 버튼 자리: 아래 고정, 꽉 차게 — 모바일: 엄지가 닿는 곳
- 장바구니·합계 자리: 하단 고정 바 — 모바일: 엄지 닿는 곳에 합계와 버튼
- 여러 단계 흐름 (두 번 되면 안 되는 작업 기준): 단계 표시줄 — 가끔 쓴다: 어디쯤인지 알려준다 / 두 번 되면 안 되는 작업: 결제 전에 몇 단계가 남았는지 보여준다
- 긴 글 (두 번 되면 안 되는 작업 기준): 말줄임 — 사진 중심: 카드 높이를 맞춘다
- 사진이 없을 때: 빈 자리 표시 — 사진 중심: 격자가 깨지지 않게 자리를 지킨다
- 상태 표시: 칩 — 
- 시간 표기 (두 번 되면 안 되는 작업 기준): 3분 전 — 가끔 쓴다

## 디자인 시스템 기준
- 불러오는 동안: 1초 안에 끝나면 로딩 표시를 하지 않는다. 깜빡이는 것이 더 느리게 느껴진다 (당근, KRDS, Primer, Ant)
- 불러오는 동안: 기다리는 시간으로 고른다. 짧으면 스피너·스켈레톤, 3~4초를 넘으면 진행 바와 안내, 아주 길면 뒤에서 처리하고 취소를 준다 (당근, Primer)
- 불러오는 동안: 가능한 한 빨리 무엇이든 보인다. 빈 화면은 고장 난 것처럼 보인다 (Apple)
- 불러오는 동안 › 스켈레톤: 목록·카드·표처럼 틀이 정해진 곳에만. 정적인 것·버튼·모달에는 쓰지 않는다 (Carbon, 원티드, 당근)
- 버튼을 누른 뒤: 보내는 버튼은 두 번째 누름을 무시한다. 서버에서도 막는다 (KRDS, GOV.UK, Carbon)
- 비어 있을 때: 처음이라 비었는지, 검색·필터 결과가 없는지, 오류인지에 따라 문구를 다르게 쓴다 (Carbon, Shopify, 당근)
- 비어 있을 때 › 다음 행동 버튼: 다음에 할 일이 있으면 버튼 하나를 둔다. 막다른 길을 만들지 않는다 (Carbon, 당근, 원티드)
- 비어 있을 때 › 다음 행동 버튼: 빈 화면 컴포넌트(Empty)에 그림·제목·설명·행동 버튼 자리를 둔다 (shadcn)
- 실패했을 때: 오류가 여러 개면 위에 오류 목록을 두고 누르면 그 칸으로 간다 (GOV.UK, Primer)
- 실패했을 때 › 알림 대화상자: 바로 응답해야 하는 중대한 일에만 (Carbon, Atlassian)
- 끝났다고 알릴 때: 토스트를 쓰지 않는 곳도 있다(스크린리더가 놓친다). 그 자리 문구나 띠로 알린다 (Primer)
- 끝났다고 알릴 때 › 완료 화면: 신청·등록 흐름의 끝이나 꼭 확인해야 할 결과는 확인 페이지로 (GOV.UK, 원티드)
- 새 소식 알릴 때 › 숫자 배지: 중요한 정보에만. 광고에 쓰지 않는다 (Apple)
- 처음 안내: 온보딩은 건너뛸 수 있으니, 주요 기능은 빈 화면 안내를 따로 둔다 (Carbon)
- 처음 안내 › 가리키는 말풍선: 한 번에 하나, 페이지가 열리자마자 저절로 띄우지 않는다 (KRDS, Primer)
- 목록이 길 때 › 무한 스크롤: 키보드로 끝에 닿기 어렵다. 쓰면 페이지 번호를 같이 두지 않는다 (KRDS, GOV.UK)
- 화면 사이 이동 › 하단 탭바: 3~5개. 넘치면 「더 보기」에 숨어 찾기 어렵다 (Material, Apple, 토스)
- 가벼운 메뉴 열기: 데스크톱의 무거운 하위 작업은 옆에서 밀려 나오는 서랍으로 (Ant)
- 가벼운 메뉴 열기 › 아래 시트: 모바일은 아래 시트, iPad는 가운데 창. 보이는 닫기 버튼을 두고, 시트 위에 시트를 쌓지 않는다 (Apple, 원티드, KRDS)
- 수량 › − + 버튼: 범위가 좁을 때. 끝값에 닿으면 그 버튼을 잠근다 (당근, KRDS)
- 켜고 끄기 › 토글 스위치: 바로 적용되는 설정에 (당근, KRDS, Primer)
- 입력 확인 시점 › 칸을 벗어날 때: 이쪽을 권하는 곳도 있다. 오입력 위험이 큰 칸(금융·보안)만 이렇게 섞기도 한다 (Carbon, 당근)
- 확인 단계 모양 › 아래 시트: 결제처럼 실수로 닫히면 안 되면 끌어서 닫기를 막고 닫기 버튼을 둔다 (당근, KRDS)
- 주요 버튼 자리: 가장 강조한 버튼은 한 화면에 하나. 위험한 동작만 빨간색 (당근, KRDS)
- 사진이 없을 때 › 빈 자리 표시: 이미지가 없거나 못 불러오면 그 자리의 성격을 알리는 대체 그림을 둔다 (당근)

## 쓰지 말 것
- 보라→파랑 그라데이션 히어로
- 모든 블록에 같은 radius·그림자를 준 카드
- 이모지를 섹션 표시로 쓰기
- 순서가 없는 내용에 01 / 02 / 03 번호
- 무조건 가운데 정렬
- 아무 근거 없이 고른 Inter 한 가지 서체
- 색 기운이 없는 순수 회색(#888 계열)
- "강력한", "원활한" 같은 과장 문구
- 카드·버튼·탭마다 넣은 안쪽 그림자·빛 번짐·그라데이션
- 모든 글자를 굵게. 굵기와 크기로 위계가 서지 않는다
- 같은 종류 항목(알림 카드 등)마다 다른 배치
- 테두리도 그림자도 없이 떠서 경계가 안 보이는 레이어
- 예시 그림·미리보기마다 크기와 자리가 제각각(어떤 건 카드 폭을 채우고 어떤 건 한쪽에 붙음)
- 카드 안에 테두리 상자, 그 안에 또 회색 상자를 겹치기
- 제목과 본문이 거의 같은 크기이고 나머지는 전부 작은 회색 글
- 출처·보조 링크까지 모두 강조색이라 진짜 이동할 곳이 묻힘
- 상태(품절·마감·오류)를 색만으로 구분하기. 글자나 아이콘을 같이 쓴다
- 보라를 피해 고른 다음 기본값: 크림 바탕에 테라코타 강조, 아주 어두운 바탕에 네온 한 가지
- 둥근 카드 한쪽에 두꺼운 색 띠
- 목적 없는 반투명 흐림(글래스) 카드. 뒤에 따라 글자 대비가 바뀐다
- 제목마다 위에 붙인 자간 벌린 작은 대문자 소제목
- 한글 옆 이탤릭, 영문 기준으로 좁힌 한글 행간(본문 1.5 미만)
- 근거 없는 큰 숫자("10,000%"), "A가 아니라 B" 문장, 대시(—) 남발
