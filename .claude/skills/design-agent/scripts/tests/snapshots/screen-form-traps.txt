해당하는 실패: 읽기·누르기 어려움 2 · 헷갈림 3 (이름 뜻과 고치는 순서: references/failures.md)
- [꼭 고칠 것 · 읽기·누르기 어려움] 확대 막기: viewport에 「width=device-width, initial-scale=1, maximum-scale=1.5」. 글자가 작아 보이는 사람이 손가락으로 200%까지 키울 수 없다. user-scalable=no를 지우고 maximum-scale은 빼거나 2 이상으로 둔다(WCAG 2.2 1.4.4)
    위치: <meta>
- [꼭 고칠 것 · 헷갈림] 미리 체크된 동의: 「(선택) 마케팅 정보 수신 동의」, 「이벤트·혜택 알림 받기」, 「제3자 정보 제공 동의(선택)」가 처음부터 체크돼 있다. 읽지 않고 넘긴 사람도 동의한 것이 된다. 선택 동의는 비워 두고 쓰는 사람이 직접 고르게 하고, [필수]·[선택]을 나눠 적는다 (전자상거래법 사전선택 금지, 2025-02-14 시행 · KRDS 동의 패턴)
    위치: <input>, <input#ev>, <input>
- [꼭 고칠 것 · 읽기·누르기 어려움] 붙여넣기 막기: 「비밀번호」, 「문자로 받은 인증번호」에서 붙여넣기·복사를 막았다(onpaste·oncopy의 return false·preventDefault). 비밀번호 관리자나 인증 문자에서 옮기지 못해 손으로 다시 치다 틀린다. 막는 코드를 지운다. 확인하려고 한 번 더 적게 하는 칸이면 그 칸을 없앤다 (KRDS 개인 식별 정보 입력·로그인 패턴(붙여넣기 허용), WCAG 2.2 · 3.3.8)
    위치: <input#pw>, <input#code>
- [고치기 권함 · 헷갈림] placeholder만 있는 입력: 2칸(「이메일」, 「자기소개」)에 placeholder만 있고 이름표(label)가 없다. 적기 시작하면 placeholder가 사라져 무슨 칸인지 잊고, 옅은 회색이라 잘 안 읽힌다. 칸 위에 보이는 label을 두고(<label for>) placeholder는 「예: 010-1234-5678」 같은 예시로만 쓴다 (WCAG 2.2 · 3.3.2, KRDS 도움 패턴)
    위치: <input>, <textarea>
- [고치기 권함 · 헷갈림] 링크가 아닌 이동: 3곳(「약관 전문 보기」, 「도움말 보기」, 「이미 계정이 있어요」)이 onclick으로 다른 페이지로 간다. 링크가 아니라 새 탭으로 열기·주소 복사·가운데 클릭이 안 되고, 화면 읽기 프로그램은 버튼으로 읽어 이동인 줄 모른다. 다른 페이지로 가는 것은 <a href>로 만든다. 저장·결제처럼 일을 한 뒤 넘어가는 버튼은 그대로 둔다 (Vercel Web Interface Guidelines 「Links are links」)
    위치: <button>, <div.card>, <span>
