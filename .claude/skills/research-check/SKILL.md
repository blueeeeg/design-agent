# research-check

조사 목록 `research/README.md`를 기준으로 두 가지를 한다. 바꾸기 전에 고칠 거리를 사용자에게 보이고 고르게 한다. 스킬·데이터를 바로 고치지 않는다.

## 1. 기존 출처 다시 보기

`research/README.md`의 항목마다 「다시 볼 곳」을 열고 「마지막 확인」 뒤에 바뀐 것만 본다.

- GitHub 저장소: 그 경로의 커밋 기록과 릴리스(`gh api repos/{owner}/{repo}/commits -X GET -f path=… -f since=날짜`). 읽기만 한다
- 블로그·문서: 새 글, 바뀐 날짜, 고친 기준
- 디자인 시스템: 우리 패턴(로딩, 토스트, 삭제 확인, 폼 검증, 빈 화면, 터치 크기 등)에 걸리는 문서가 바뀌었나. 나머지 변경은 세지 않는다
- 레퍼런스 사이트: 이용 조건이 바뀌었나(`SOURCES.md` 판단이 달라지나)

바뀐 것마다 「우리 쪽에 무엇을 고칠 만한가」를 하나 적는다. 고칠 게 없으면 「바뀜, 반영할 것 없음」. 그다음 그 항목의 「마지막 확인」 날짜를 고친다.

## 2. 새로 찾기

`research/README.md` 「새로 찾을 곳」을 돈다. 찾은 것은 이 셋에 맞을 때만 후보로 낸다.

- 이 프로젝트가 하는 일(상황별 UI 패턴 고르기, AI 화면의 밤티 거르기, 색·글자·여백 재기, 디자인 시스템 위에서 만들기)에 직접 쓰인다
- 원문이 공개돼 있고 라이선스나 이용 조건을 확인할 수 있다
- 이미 목록에 있는 것과 겹치지 않는다(겹치면 기존 항목의 「바뀐 것」으로 적는다)

후보마다: 이름, 주소, 라이선스, 무엇을 하나, 우리가 가져올 생각 한 가지, 우리와 다른 점.

## 지킬 것

- 남의 코드·패키지를 설치하거나 실행하지 않는다. 읽기만 한다
- 문장·이미지를 옮기지 않는다. 생각만 우리 말로 적고 링크를 단다. 이미지는 `refs-private/`에만(`CLAUDE.md`)
- Lazyweb MCP에는 검색어만 보낸다
- 회사 안 자료, 회사 이름은 적지 않는다
- 소개 글(2차 기사)만 본 것은 「원문 못 봄」이라고 적는다. 날짜를 지어내지 않는다

## 결과

사용자에게 한국어로 이 순서로 보인다.

1. 기존 출처에서 바뀐 것과 고칠 거리(고칠 만한 것부터)
2. 새 후보
3. 확인 못 한 것(열리지 않은 곳, 로그인이 필요한 곳)

사용자가 고른 것만 반영한다. 반영하면 `research/README.md` 항목을 고치고, 스킬·데이터를 고친 것은 `HANDOFF.md` 기록과 `LEARNED.md`(배운 것이 있으면)에 적는다.
