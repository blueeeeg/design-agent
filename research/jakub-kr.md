## 스킬 모음의 짜임

- `/better-ui`(모서리·광학 정렬·그림자·움직임·아이콘), `/better-typography`, `/better-layout`, `/better-colors`, `/better-accessibility`, `/better-writing`
- `/interface-review`: 화면 전체가 아니라 브랜치에서 바뀐 코드만 본다. 바뀐 파일을 쓰는 곳까지 한 단계 넓히고, 걸린 것마다 「이번에 생김 / 전에 되던 게 깨짐 / 원래 있던 것」을 붙인다. 원래 있던 것은 3개까지만 보인다
- `/make-interfaces-feel-better`: 아래 「세부를 다듬는 글」을 스킬로 만든 것
- 결과 모양이 같다: 심각도(HIGH·MEDIUM·LOW), 위치, 전·후, 이유를 한 줄씩. 빠른 모드는 5개, 전체는 15개까지. 「검토했지만 뺀 것」을 따로 적고, 끝에 막음 / 고쳐야 함 / 통과
- 브라우저에서 확인 못 하면 「확인 못 함」이라고 적는다(우리 「확인 못 한 것」과 같은 생각)
- 접근성 스킬은 WCAG 항목 번호나 「보조기기 사용자가 끝내지 못하는 일」을 댈 수 있을 때만 높은 심각도를 준다. 나머지는 권장으로 낮춘다(우리 「규격 > 관례」와 같은 생각)

## 우리에게 없는 것 (검사로 만들 수 있는 것부터. 2026-11-10 반영)

- **겹친 모서리**: 안쪽 상자가 바깥 상자 안에 있으면 바깥 모서리 = 안쪽 모서리 + 안쪽 여백(+ 테두리). 여백이 24px를 넘으면 따로 떨어진 면으로 보고 맞추지 않는다. 우리는 모서리 종류만 센다
- **묶음 사이 여백**: 묶음 사이 간격이 묶음 안 간격의 2배 이상(예: 안 8px, 사이 16px 이상). 우리는 제목 위·아래 여백만 본다
- **숫자 자리 맞춤**: 바뀌는 숫자(타이머, 수량, 가격, 표의 숫자 열)에 `tabular-nums`. 우리는 고정폭 라벨 알림에서 말로만 권한다
- **`transition: all`**: 바뀌는 속성을 이름으로 적는다. CSS에서 바로 찾을 수 있다
- **hover를 `@media (hover: hover)` 안에**: 터치 기기에서 누른 뒤 hover 모양이 남는다. 태블릿·모바일 조건에서 의미가 크다
- **얇은 굵기**: 100~300 굵기는 28px 이상에서만. 18px 아래는 400 이상
- **자주 하는 동작은 움직이지 않는다**: 하루 200번 여는 메뉴에 300ms 움직임이면 하루 1분, 1년에 6시간이 넘는다는 계산. 키 입력, 행 hover, 탭 바꾸기는 바로 또는 150ms 이하. 우리 「얼마나 자주 쓰나요?」 조건과 바로 맞물린다(매일 쓰는 업무 도구는 움직임을 줄인다)
- **누를 때 줄어듦**: 0.96배, 150ms. 0.95배 아래로 줄이지 않고 꺼진 버튼은 줄이지 않는다
- **나갈 때는 들어올 때보다 약하게**: 들어올 때 투명도 + 흐림 4px + 위아래 12px 300ms라면, 나갈 때는 150ms에 짧게. 서랍만 끝까지 밀어 넣는다
- **문구**: 대화상자 버튼에 「확인」「예」「아니오」 대신 하는 일을 동사로(「프로젝트 삭제」). 「정말 하시겠어요?」 대신 무엇을 지우는지 제목에 적는다. 작업 공간·저장소처럼 큰 것을 지울 때는 이름을 입력하게 한다. 켜고 끄는 스위치 이름은 켰을 때 상태로 적는다. 빈 화면은 「여기가 무엇인지 + 다음 할 일 하나」
- **접근성 몇 가지**: 끌기 동작에는 한 번 눌러서 하는 다른 길(WCAG 2.5.7), 5초 넘게 저절로 움직이는 것에는 멈춤(2.2.2, 자동 넘김 배너), 입력이 다 맞을 때까지 제출 버튼을 잠그지 않는다(제출할 때 검사하고 첫 오류로 이동)
- **색**: 상태색(빨강·초록·노랑)이 강조색과 OKLCH 색상각 15도 안이면 15도 넘게 떼어 놓는다. 흰 글자를 올릴 채운 색은 Tailwind 500 단계면 대개 모자라고 600으로

## 우리와 이미 같은 것

- 대비 4.5:1·3:1, 입력칸 테두리 3:1, 누를 곳 24px(WCAG 2.5.8)와 44·40px 관례, 모바일 입력칸 16px, 확대 막기 금지, 움직임 줄이기 설정, 아이콘 채움·선 섞임, 그라데이션은 oklab 기본, 되돌릴 수 있으면 확인창보다 되돌리기

## 넣지 않을 것

- 영문 기준 조판: 헤드라인 자간 음수, 대문자 라벨 자간, 곡선 따옴표, 한 줄 60~75자(한글은 기준이 다르다). `text-wrap: balance`는 한글에도 되지만 한글 줄바꿈은 `word-break: keep-all`이 먼저다
- 취향에 가까운 값: 테두리 대신 세 겹 그림자, 사진 외곽선 1px 10%, 글자 매끄럽게(`antialiased`), 들어오는 움직임 800ms 곡선(글과 스킬의 값이 서로 다르다)
- 아이콘 선 굵기: 두 스킬의 값이 서로 다르다(글자 굵기 400 옆 1.5px은 같고, 그 위가 다르다)
- `/teardown`(물건 분해도 그리기)과 Motion 라이브러리 사용법 글: 화면 패턴과 상관없다

## 나머지 스킬의 일하는 방식 (2026-11-10 추가)

값이 아니라 순서와 장치를 봤다. 연 파일: `better-interface`, `afk`(PR #58 설명까지), `break`, `variant`, `explain-interface`, `state-machine`의 SKILL.md, `AGENTS.md`, `better-ui`의 참고 파일 둘. 못 연 것: 각 스킬의 딸린 파일(`review-format.md`, `scenarios.md`, `picker.md`, `switcher.md` 등)

- **`/state-machine`**: 컴포넌트 하나가 가질 수 있는 상태(불러오는 중, 비었음, 오류, 하나, 아주 많음, 일부만 옴, 권한·요금제별)를 코드에서 찾아, 임시 페이지에 진짜 컴포넌트를 두고 `?__state=` 주소로 바꿔 본다. 코드에 없는 상태는 새로 만들지 않고 「빠졌다」고 적는다. 상태 이름은 그 서비스가 쓰는 말로. 화면에 안 나오는 상태가 있으면 데이터 연결이 깨진 것으로 본다
- **`/variant`**: 하나를 세 가지로 일부러 다르게 만든다. 먼저 어느 축(구조, 빽빽함, 강조, 글자, 말투)에서 다르게 할지 정하고, 이름은 「A안」이 아니라 방향(조용한, 빽빽한)으로. 실제 페이지 안에 고르는 칸을 두고 진짜 문구·진짜 개수로 하나씩 크게 보인다. 장단점을 보여 주되 하나를 추천하지 않는다. 고르면 나머지와 고르는 칸을 지운다
- **`/break`**: 컴포넌트 하나를 여러 극단 상황(긴 글, 빈 값, 좁은 폭 등)으로 한 페이지에 나란히 띄우고 한 번만 본다. 「다 버텼다」도 결과다. 고치지 않는다
- **`/better-interface`**: 분야 스킬을 접근성 → 배치 → 문구 → 글자 → 색 → UI 순서로 불러 한 보고서로 묶는다. 시작할 때 그 프로젝트의 문서(AGENTS.md, CLAUDE.md, 디자인 시스템 문서, Storybook)를 읽고 무엇을 찾았는지 밝힌다. 장치:
  - 확인되면 늘 높음인 조건 13개(이름 없는 컨트롤, 포커스 링 없음, 320px·200% 잘림, 대비 미달, 색만으로 뜻, 확인 없는 삭제 등)
  - 고치는 법은 싼 것부터: 지운다 → 브라우저 기본 기능을 쓴다 → 프로젝트 토큰을 쓴다 → 값을 고친다 → 더한다
  - 원인 하나는 한 줄, 15개까지, 채우려고 늘리지 않는다
  - 돌려 보지 못한 것은 「확인 못 함」이지 걸린 것이 아니다. 불러오지 못한 분야는 「안 봄」
- **`/afk`**: 사용자가 없는 동안 따로 브랜치에서 일한다. 아이디어를 15개 넘게 낸 뒤 고르고, 바꾼 것마다 「틀렸다고 증명해 보기」(다른 화면, 새로고침·뒤로, 기본 브랜치와 비교, 바꾸기 전에는 테스트가 실패하나)를 거쳐 그대로 둠 / 줄임 / 되돌림 중 하나로 끝낸다. 보고서에 「되돌린 것」「안 본 것」「사용자가 정할 것」을 따로 둔다
- **`/explain-interface`**: 공개 페이지나 스크린샷으로 「이건 어떻게 만들었나」를 설명한다. 말마다 잰 것 / 계산한 것 / 짐작한 것을 붙인다. 스크린샷만 있으면 「설명」이 아니라 「다시 그려 본 것」이라고 밝힌다
- **저장소 짜임**
  - 스킬마다 폴더 하나로 따로 설치되고, 같은 규칙은 한 스킬에만 둔다. 다른 스킬은 이름으로만 가리킨다
  - 사용자가 불러야만 도는 스킬(`disable-model-invocation: true`)과 알아서 도는 스킬을 나눈다
  - 플러그인으로 배포하고, 스킬을 고치면 같은 커밋에서 `plugin.json` 버전을 올린다
  - 저장소 사실은 `AGENTS.md` 한 곳에 두고 `CLAUDE.md`는 그것을 불러온다
- **시험**: 평가 묶음이 없다. 그림 그리는 스킬 하나에만 스크립트 테스트가 있고, 나머지는 글 점검(문장 30단어 이하, 설명 = README 한 줄 등)이다. 이 부분은 우리 쪽(효과 비교 3회)이 더 앞서 있다

### 우리에게 쓸 만한 것 (2026-11-10 모두 반영. `disable-model-invocation`만 뺐다)

- `/state-machine` → 6단계에서 화면을 다 만든 뒤, 고른 패턴의 상태(불러오는 동안, 빈 화면, 오류, 아주 많음)를 주소 하나로 바꿔 보게 한다. 지금 검사는 「빈 화면이 없다」는 찾지만, 있는 빈 화면이 어떻게 보이는지는 보여 주지 않는다
- `/variant` → 4단계에서 방식을 말로만 고르게 하지 말고, 사용자의 실제 화면에 두세 방식을 바꿔 끼워 보게 한다. 브랜드 방향 2~3가지 제안(`visual-basics.md`)에도 같은 틀을 쓴다. 다만 우리는 조건에 맞는 추천을 표시한다(추천하지 않는 것은 그쪽의 선택)
- `/break` → 한글 긴 글, 가격 최대 자릿수, 320px, 글자 200%를 한 페이지에 나란히(마디아 노트 「글 1·2·3줄」, giting hangul-wrap과 같은 방향)
- `/better-interface` → 리뷰 쓰는 법에 「싼 고치기부터(지우기 먼저)」, 「원인 하나는 한 줄」, 「채우려고 늘리지 않기」. 1단계에서 프로젝트 문서를 먼저 읽고 찾은 것을 밝히기
- `/explain-interface` → 리뷰 숫자에 「잼 / 계산 / 짐작」 붙이기(지금은 「소스로 어림한 값」만 밝힌다)
- `/afk`의 「틀렸다고 증명해 보기」 → 고친 뒤 검사를 다시 돌리는 것에 더해, 고친 것이 다른 화면·좁은 폭에서 깨지지 않았나 보기
- `disable-model-invocation` → `research-check`처럼 사용자가 부를 때만 도는 스킬에 붙일 수 있다
