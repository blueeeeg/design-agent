# UX 기준을 어떤 갈래로 모으나 — 해외·국내 분류 비교

확인: 2026-11-11. 서브에이전트 둘이 공개 자료를 읽었다(해외 모음·체계 하나, 국내 자료 하나). 문장은 옮기지 않고 분류와 생각만 적는다. 표시가 없는 것은 원문을 열어 확인했고, 「간접」은 검색 요약·2차 기사로만 봤다.

## 왜 봤나

`/ux/`와 `references/ux-basics.md`의 다섯 갈래(사고 위험, 키보드와 초점, 할 일이 보이나, 누른 뒤, 말)는 2026-11-11 내부 도구 화면 비교에서 드러난 빈틈으로 만든 것이라 좁았다. 다른 곳이 UX 지침을 어떤 갈래로 모으는지 보고 빠진 갈래를 찾았다.

## 해외

- **NN/g 10가지 휴리스틱** https://www.nngroup.com/articles/ten-usability-heuristics/ — 상태 보이기, 현실과 맞는 말, 통제와 되돌리기, 일관성, 오류 예방, 기억보다 알아보기, 효율(단축키), 군더더기 없음, 오류 회복, 도움말. 기억·효율·군더더기·도움말에 맞는 우리 갈래가 없었다
- **Laws of UX** https://lawsofux.com/ — 30개, 묶음 없음. 규칙보다 근거로 쓰기 좋다
- **점검표**
  - A11y Project https://www.a11yproject.com/checklist/ — 16절(내용, 전역 코드, 키보드, 이미지, 제목, 목록, 컨트롤, 표, 폼, 미디어, 겉모습, 움직임, 대비, 모바일·터치 등)
  - Primer 디자이너 체크리스트 https://primer.style/accessibility/tools-and-resources/checklists/designer-checklist/ — 8절(색, 위계, 내용, 이미지, 상호작용, 폼, 배치, 키보드)
  - Vercel Web Interface Guidelines https://vercel.com/design/guidelines — 상호작용, 움직임, 배치, 내용, 폼, 성능, 디자인, 문구
  - ux-checklist.com — 조사부터 분석까지 9단계
  - Built for Shopify https://shopify.dev/docs/apps/launch/built-for-shopify/requirements — 디자인 요건을 익숙함·도움·사용자 친화(거짓 주장·압박·방해·과부하 금지)로 나눈다
- **패턴 모음**: GOV.UK(묻기 / 돕기 / 페이지), Carbon 패턴 17개, Apple HIG 패턴 25개, UI-Patterns.com(입력, 온보딩, 탐색, 데이터, 사회, 설득), uxpatterns.dev 11묶음, Baymard 9주제, Smart Interface Design Patterns 강의 41개
- **속이는 설계**: deceptive.design 18종 https://www.deceptive.design/types , FTC 「Bringing Dark Patterns to Light」(2022-09) https://www.ftc.gov/reports/bringing-dark-patterns-light , EDPB 지침 03/2022(간접)
- **인지·포용**: W3C COGA https://www.w3.org/TR/coga-usable/ 목표 8개(무엇인지 알게, 찾게, 분명한 말, 실수 피하고 고치게, 집중하게, 기억에 기대지 않게, 도움, 맞춤), Microsoft Inclusive Design 원칙 3개

여러 출처에 되풀이되는 큰 영역은 약 20개다: 상태와 피드백, 오류 예방, 오류 회복, 되돌리기·출구, 길찾기, 찾기·거르기·표, 입력·폼, 일관성, 키보드·초점, 보조기술이 읽는 의미, 보기(대비·확대), 움직임, 터치, 말, 체감 속도, 속이지 않기, 계정·권한·개인정보, 도움·온보딩, 방해·인지 부담, 기억에 기대지 않기, 개인화, 빈·경계 상태, 여러 단계.

## 국내

- **KRDS** https://www.krds.go.kr/html/site/index.html
  - 기본 패턴 12개: 개인 식별 정보 입력, 도움, 동의, 목록 탐색, 사용자 피드백, 상세 정보 확인, 오류, 입력폼, 첨부 파일, 필터링·정렬, 확인, 모바일 알림 https://www.krds.go.kr/html/site/global/global_summary.html
  - 서비스 패턴 5개: 방문, 검색, 로그인, 신청, 정책 정보 확인. 규칙마다 필수·권장·우수 https://www.krds.go.kr/html/site/service/service_summary.html
  - 기본 패턴 페이지는 사용성 / 접근성(KWCAG·WCAG 항목 연결) / 상호작용 세 칸
  - 눈에 띈 규칙: 플레이스홀더를 레이블 대신 쓰지 않는다, 개인 정보 입력은 붙여넣기 허용·미리 채우지 않기·autocomplete, 동의는 「동의 안 함」과 [필수]·[선택], 만족도 요청은 작업 뒤 아래쪽에 질문 3개까지, 세션 만료는 20초 전에 연장·로그아웃, 알림은 급한 정도로 채널을 나눈다
  - 자체 검증 체크리스트(HWP)는 받지 못했다
- **KWCAG 2.2** 4원칙(인식·운용·이해·견고) 아래 흐름에 관한 항목: 자동 재생 금지, 초점, 응답 시간 조절, 정지 기능, 예고 없이 바뀌지 않기, 찾기 쉬운 도움, 오류 정정, 접근 가능한 인증, 반복 입력 정보(2.2 신규 9개는 간접)
- **고령자 친화적 모바일 금융앱 구성지침**(금융위·금감원, 2022-02) — 고령자 모드는 사용자가 고르고, 메인에서 2번 이하 터치, 쉬운 말(여신 → 대출), 5단계 이상이면 전체와 현재 단계 표시, 시간 제한 연장
- **토스(앱인토스)** https://developers-apps-in-toss.toss.im/design/consumer-ux-guide.html — 다크패턴 방지 다섯(들어오자마자 광고·알림 시트, 뒤로 가기를 막는 시트, 나갈 길 없음, 예상 못 한 전면 광고, 버튼만 보고 결과를 모름), UX 라이팅, 출시 체크리스트(권한은 거부해도 나머지가 돌아가야, 지연 2초 미만, 결제 실패 사유)
- **당근 SEED** https://seed-design.io/llms.txt — 포용 디자인의 사용자 조절(시스템 글자 크기, 애니메이션 끄기·2초 넘으면 건너뛰기, 자동 재생 기본 끄기)
- **공정위 다크패턴**: 2023 자율관리 가이드라인 4범주(편취·오도·방해·압박, 간접), 2025-02-14 시행 전자상거래법 개정 6유형(숨은갱신, 순차공개 가격, 사전선택, 잘못된 계층구조, 취소·탈퇴 방해, 반복간섭, 간접), 2026-10-06 운영 가이드라인 13유형(간접)
- 카카오·우아한형제들·네이버·원티드는 공개된 UX 지침을 찾지 못했다

## 우리 구성과 견준 것

- **패턴 28개가 이미 덮는 것**: 상태와 피드백(로딩, 누른 뒤, 끝났다고 알릴 때, 새 소식), 오류, 찾기·거르기·목록, 처음 안내, 빈 화면, 여러 단계. 패턴은 「어느 방식을 쓸까」에 답하고, 「어느 방식이든 지킬 것」은 UX 기준이 맡는다
- **UX 다섯 갈래가 덮는 것**: 파괴 동작, 키보드·초점, 상태 보이기, 누른 뒤 피드백·오류, 버튼 이름·말투
- **아무 데도 없던 것**: 입력·폼 공통 규칙, 길찾기, 키보드 밖의 접근성(확대, 움직임·자동 재생·시간 제한, 터치), 속이지 않기(사전선택, 잘못된 계층구조, 죄책감 주는 거절, 숨은 비용, 해지 방해), 끼어들기(들어오자마자 뜨는 창, 반복 간섭, 뒤로 가기 막기), 동의·개인정보·권한
- **새 패턴 후보**(상황마다 방식을 고르는 것): 동의 받기, 권한 요청 시점, 세션 만료 알림, 로그인 권유, 해지·탈퇴 경로, 만족도 요청, 도움말 방식, 신청 뒤 진행 상태
  - 2026-11-12: 여섯을 패턴으로 만들었다(동의 받기, 권한 요청, 세션 만료 알림, 만족도 요청, 도움말 방식, 신청 뒤 진행 상태). 로그인 권유·해지·탈퇴 경로는 UX 기준 방해-5·속임-5가 답 하나를 주니 넣지 않았다. 근거는 `research/README.md` 「새 패턴 여섯의 근거」
